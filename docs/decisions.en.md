# Architecture decision index (English)

[中文](decisions.md) · English

> This is an English index of the architecture decisions. The full evidence chains, alternatives and implementation notes are in the Chinese [decisions.md](decisions.md). Each entry states the adopted decision in one paragraph.

| ADR | Decision |
| --- | --- |
| **0001** Policy language boundary | Use a small typed policy language rather than a general DSL. Add URI-specific prefix/glob operators for resources, with segment-aware matching (`*` does not cross `/`, `**` does). The schema has a `resources:` section beside `tools:`. |
| **0002** Budget semantics | `reserve → commit / release`, backed by SQLite (WAL), an in-process single writer and database constraints. Reserve uses an IMMEDIATE transaction and conditional update; the idempotency key is `(session_id, tool_call_id)`; expired holds are reclaimed and reconciled at startup. |
| **0003** Evidence semantics | Two shapes: a global hash chain (one row per call, including denies) and a run package (JSONL + manifest with a Merkle root). Canonicalization uses key sorting; non-deterministic fields are recorded inputs; `verify` and `replay` are separate commands. |
| **0004** Transport choice | Different transports on the two edges: Streamable HTTP toward the agent (standalone process, multiple clients, observable, restartable) and stdio toward mocks (child process, no ports or network configuration, easiest to reproduce). |
| **0005** SDK proxy capability and forwarding | The SDK has no built-in proxy. The downstream side uses `MCPServer` mounted as an ASGI app with `ServerMiddleware` as the interception hook; forwarding itself is written in `enforce/` using `ClientSession` + `stdio_client`. |
| **0006** Approval gate | Prefer protocol-native `input_required` / MRTR. Keep approval pause state in `requestState`; persist only approvals that must survive restart, safely bound to session/user. CLI is a fallback. Approvals bind an action fingerprint, are single-use, fail closed, and time out to deny. |
| **0007** Shape of policy denial | Three layers: pre-call policy context, adaptive in-call denial as a tool execution error (`isError: true`) with a category-level reason, and hard denial minimized; structural errors use JSON-RPC protocol errors. A policy decision is a business result, not a protocol error. |
| **0008** Tool-name disambiguation | Prefix aggregated tools with the configured server alias: `<alias>__<tool>`. Duplicate aliases or collisions after prefixing fail at startup. The mapping is recorded in evidence. |
| **0009** `x-mcp-header` | Do not use it actively. Preserve upstream-declared `Mcp-Param-*` headers when forwarding; the policy layer checks whether sensitive parameters were mirrored into headers and denies or alerts. |
| **0010** `tools/list` filtering and caching | Cache upstream lists by (upstream identity, upstream cursor); return lists keyed by authorization fingerprint and never reuse across authorizations. If upstream says `cacheScope: public` while filtering depends on the agent, tighten the output to `private`. |
| **0011** Interception surface | Intercept every method that can read data or change state: `tools/*` and `resources/*` (including `prompts/get`), excluding methods such as `ping` and `logging`. I1 becomes "no method call is allowed without a Decision." |
| **0012** Capability exposure and aggregation | Keep resources and filter by URI through policy; advertise the union of capabilities; declare `subscribe: true` only after notification filtering exists; provide an `expose_resources: false` switch; namespace tools and resources. |
| **0013** Pagination and filtering | Fetch-through filling + self-signed opaque cursors + AIP-158 degraded-skip semantics + at most 5 upstream pages per client request; cache by (authorization fingerprint, upstream cursor) without cross-authorization reuse. |
| **0014** Explicit type-class lists | Maintain `PASSTHROUGH` / `CONSTRUCTED` / `VALIDATED` lists in code, with CI checking golden tests for constructed types and negative tests for validated types. Promotions become visible in diffs. |
| **0015** Evaluation scope and method | Make evaluation a first-class deliverable: `eval/`, `docs/evaluation.md`, a results table and a curve. Metrics cover control-plane invariants, authorization binding, approval, robustness and cost/latency. |
| **0016** Driver implementation | Write the thin driver ourselves (~100–150 lines: MCP client + fixed action sequence + optional LLM decision), reusing mini-swe-agent's loop experience. Using a full harness is future work. |
| **0017** Gateway-owned session state | 2026-07-28 has no protocol-level session. The gateway defines `session_id = agent identity + run id`, established with the first request and recorded in evidence. Budget, approval and evidence aggregate by it; TTL and an explicit close command reclaim it; the key is never exposed upstream. |
| **0018** Version handling | Per-edge negotiation without translation. Each hop's `_meta.protocolVersion` reflects that hop's actual implementation; startup uses `server/discover` to probe upstream and fails fast if unsupported; runtime mismatch returns `-32022`; no cross-version translation. |
| **0019** Identity and credential model | Add `identity/`: `validate_inbound` produces an `AuthorizationBasis`, `CredentialProvider` supplies upstream credentials. The demo uses static credentials; token exchange and URL-mode authorization are interfaces. Downstream validation is real; evidence records `authz_basis`. |
| **0020** Composing authorization and policy | Two layers with AND: `scope allowed ∩ policy allowed`. Any unknown layer denies (fail closed). Each layer emits its own `reason_code`; evidence records both; `Decision` carries `decided_by: authz | policy | both`. |
| **0021** Approval channel and sensitive data | Non-sensitive confirmation uses form mode (boolean/single choice, validated against `requestedSchema`). Any sensitive information (payment credentials, secrets, third-party authorization) uses URL mode; the gateway only relays the URL and context; the URL must not contain sensitive data or be pre-authenticated. Approval binds to a specific client and user; there is no global "approve" entry. |
| **0022** Differentiation from JanuScope | Position the project as a controlled execution and verification control plane for agentic commerce/pay. Do not compete on general proxy capability. Borrow audit-first ordering, explicit denied-path evidence and capability honesty; differentiate with transaction context, budget and commerce-specific policy. |
| **0023** Resources denial shape | `resources/list` filters by caller authorization (allowed by the spec; cursors re-signed per ADR-0013), making "not found" the default. For a URI that never appeared in `list`, `resources/read` returns `-32602`, `"Resource not found"`, `data.uri`, with **no** `reason_code`, indistinguishable from a missing resource. Full reasons go only to the evidence ledger. |
| **0024** Agent-edge protocol era | Prefer the modern era (`2026-07-28`) on the agent edge. The gateway serves both eras, but docs, demos and evaluation use the modern era. The driver uses `mode="auto"` and does not pin a version. Capability advertising is explicit per ADR-0012. |
| **0025** Driver and model client reuse | Keep a self-written driver. Do not implement LiteLLM at all; keep the `ModelClient` interface because record-and-replay must be able to replace model calls, not merely switch providers. Default implementation uses the `openai` SDK. |
| **0026** Division of labour | The user sets direction and makes decisions; AI implements and maintains the project. Keep the code clean and readable for later study. The rule that every resume module must be reproducible by hand is relaxed to "the user can explain and defend every module." |
| **0027** Budget measurement: authorization or capture | Only calls that actually move money reserve budget. A `reserves_budget` flag defaults to true; `create_payment_intent` is set false, and `capture_payment` is the budgeted event. This avoids double-counting the same money. |
| **0028** Reconstructability of replay inputs | Two-level evidence with verifiable binding: the chain keeps only `args_digest` and `policy_digest`; a separate `runs/<run_id>.inputs.jsonl` stores `{seq, arguments}` under separate access control. `reconstruct()` verifies each digest against the chain and recomputes decisions with the real policy. Report precondition rate and decision reconstruction rate separately. Adopted 2026-10-16. |
| **0029** Transaction context and cross-call invariants | Add a demo transaction guard: one active intent per checkout, amount binding to the cart total, capture before complete, exact PSP-issued token, and a per-mandate transaction limit. The guard is in-process; SQLite persistence, multicapture, refund accumulation and signed quotes are TODO. |

## Decision process

Every architecture change requires: (1) a concrete problem and affected invariants, (2) external evidence or a reproducible probe, (3) alternatives with trade-offs, (4) an explicit user decision, and (5) tests or a documented boundary. Decisions are never silently changed in code; a change that cannot fit an existing ADR requires a new ADR.
